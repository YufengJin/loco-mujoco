# loco-mujoco — Benchmark Guide

Generated by `benchmark-generator` skill. English-only by contract; regenerated on every re-run.

## About

LocoMuJoCo is an imitation-learning **and** RL benchmark for whole-body locomotion control on humanoids and quadrupeds. The README markets it as "an imitation learning benchmark", but the env interface is RL: `env.step()` returns a shaped reward via `LocomotionReward`, `RLFactory` is the default factory, and the in-tree baselines (PPO, GAIL, AMP, DeepMimic-via-`jax_rl_mimic`) all consume the same gym-style step contract. Imitation tasks are an `ImitationFactory` flavour layered on top.

The benchmark ships 12 humanoid robots, 4 quadruped robots, and two motion-capture corpora (AMASS, LAFAN1) for imitation tasks. The JAX/MJX backend can run thousands of envs in parallel on a single GPU; the package layers a modular plug-in design on top of MuJoCo where rewards, observations, control modes, terrains, terminations, and domain-randomizers are all interchangeable components passed at env construction.

| Field | Value |
|-------|-------|
| Simulator | MuJoCo 3.7 + MJX 3.7 + mujoco-warp 3.7 |
| Benchmark category | **RL** (with optional imitation tasks via `ImitationFactory`) |
| Upstream paper / project | Al-Hafez et al., "LocoMuJoCo: A Comprehensive Imitation Learning Benchmark for Locomotion" — https://github.com/robfiras/loco-mujoco |
| License | MIT |
| Primary use case | whole-body locomotion (humanoid + quadruped), RL + imitation |

Each humanoid / quadruped env has both a CPU MuJoCo flavour (e.g. `UnitreeH1`) and an MJX flavour (e.g. `MjxUnitreeH1`) — pick the MJX variant when training on GPU.

### Task groups

The "task" axis on top of an env is set by `task_factory` + `goal_type` + `reward_type`:

- `RLFactory` — pure RL, no dataset. Goals like `GoalRandomRootVelocity` (track a random commanded velocity) drive the reward; `LocomotionReward` shapes 7 weighted terms (XY/yaw tracking, air time, joint torque, action rate, energy, joint limits, symmetry).
- `ImitationFactory` — pulls a motion-capture dataset (AMASS, LAFAN1, or a native dataset) and generates imitation rewards (DeepMimic-style or AMP-style) that follow a target trajectory.

## Action / Observation spaces

| Field | Value |
|-------|-------|
| Action dim | per env (UnitreeH1: `19` joint targets) |
| Action semantics | continuous joint position / torque targets in `[-1, 1]`, scaled by the env's actuator limits |
| Observation type | low-dim float vector — root pose / velocity, joint positions / velocities, optional goal / phase channels (UnitreeH1: 52-D) |
| Control frequency | env-specific (typically 50 Hz for MJX humanoids; check `env.info.dt`) |
| Reward signal | dense, multi-term shaped reward via `LocomotionReward` (RL) or trajectory-imitation reward (`MimicReward`, `AMPReward`) for IL |

## How to use

The skill produced two receipt files at the repo root — `history.md` (what the skill did) and this file (what the benchmark *is*). `install.md` is owned by `env-generator` and describes how to build the image. The flow below assumes you have already followed `install.md` and have a running container.

### 1. Enter the container

```bash
docker compose -f docker/docker-compose.headless.yaml up -d
docker compose -f docker/docker-compose.headless.yaml exec loco-mujoco bash
```

### 2. Pick a task

```bash
# List available robot envs
python -c "
import pkgutil
import loco_mujoco.environments.humanoids as h
import loco_mujoco.environments.quadrupeds as q
def names(pkg):
    return sorted([m.name for m in pkgutil.iter_modules(pkg.__path__) if not m.name.startswith('base_')])
print('humanoids:', names(h))
print('quadrupeds:', names(q))
"
```

Any identifier from the task table above is a valid value for `--env_name`. The MJX variant prefix (`Mjx<Name>`) selects the GPU-vectorised env class instead of the CPU MuJoCo class.

### 3. Train a policy

This benchmark uses **dispatcher mode**: `scripts/train_rl_policy.py` routes `--algo` to the matching upstream `experiment.py`. There is no `train_rl_policy_sb3.py` — loco-mujoco's training stack is JAX-native (PPOJax, GAILJax, AMPJax) and does not depend on stable-baselines3.

```bash
python scripts/train_rl_policy.py --algo ppo \
    experiment.total_timesteps=1_000_000
```

Supported algorithms for this benchmark: `ppo, gail, amp, rl_mimic` (baselines mode: `dispatcher` — delegates to `examples/training_examples/jax_<algo>/experiment.py`).

For a fast smoke check (≤ 1 minute on an RTX 4090):

```bash
WANDB_MODE=disabled python scripts/train_rl_policy.py --algo ppo \
    experiment.total_timesteps=5000 experiment.num_envs=4 \
    experiment.num_steps=16 experiment.num_minibatches=2 \
    experiment.debug=true experiment.validation.active=false
```

Hydra overrides go after `--algo`. Common knobs:

- `experiment.env_params.env_name=MjxUnitreeH1` — switch robot.
- `experiment.task_factory.name=ImitationFactory` — switch to imitation mode (requires AMASS / LAFAN1 path configured).
- `experiment.num_envs=2048` — vectorise heavily on a beefy GPU.
- `WANDB_MODE=disabled` — silence wandb when iterating locally.

### 4. Evaluate a checkpoint

```bash
python scripts/run_eval.py --checkpoint_path outputs/<date>/<time>/PPOJax_saved.pkl \
    --algo ppo --n-envs 1 --n-steps 1000 --deterministic
```

`scripts/run_eval.py` reconstructs the env from the embedded `agent_conf.config` (no need to pass `--env_name`). Use `--use_mujoco` to replay on the CPU MuJoCo backend instead of MJX, and `--record` to dump an MP4 to `LocoMuJoCo_recordings/`.

Each invocation writes a per-run log to `<log_dir>/eval/<env>--<YYYYMMDD_HHMMSS>/eval.log` (default `--log_dir ./logs`).

### 5. Single-episode demo (no checkpoint required)

```bash
python scripts/run_demo.py --env_name UnitreeH1 --n-steps 50
```

Random actions on a plain `RLFactory` env — useful for sanity-checking that the env builds, the renderer is wired, and the per-step reward is finite. Add `--checkpoint_path <path> --algo ppo --deterministic` to swap random actions for a trained policy.

### 6. Use the imitation dataset

For imitation tasks, configure the dataset paths once per host:

```bash
loco-mujoco-set-amass-path <path-to-AMASS>
loco-mujoco-set-lafan1-path <path-to-LAFAN1>
loco-mujoco-download                # fetch all native datasets from HuggingFace
loco-mujoco-myomodel-init           # opt-in MyoSkeleton (license acceptance)
```

Then build an imitation env:

```python
from loco_mujoco import ImitationFactory
env = ImitationFactory.make("UnitreeH1", task="walk")
```

The companion training entrypoints `examples/training_examples/jax_gail/experiment.py`, `examples/training_examples/jax_amp/experiment.py`, and `examples/training_examples/jax_rl_mimic/experiment.py` consume these envs directly through the dispatcher (`--algo gail|amp|rl_mimic`).

## Troubleshooting

- `RuntimeError: cannot find LOCOMUJOCO_VARIABLES.yaml` → first import did not complete. Re-enter the container; `entrypoint.sh` runs `python -c "import loco_mujoco"` once at start to write the file.
- `HuggingFaceHub: dataset gated` → run one of the `loco-mujoco-download-*` CLIs (or a `huggingface-cli login`) to seed the cache.
- `MyoSkeleton` errors during `ImitationFactory.make("MyoSkeleton", ...)` → set `LOCO_AUTO_MYO=1` and restart the container, or run `loco-mujoco-myomodel-init` interactively.
- GUI apps fail with `cannot open display` → you are on the headless compose profile. Switch to `docker-compose.x11.yaml` after `docker compose down`.
- `algo entrypoint not found` from `scripts/train_rl_policy.py` → upstream renamed a training example. Edit `ALGO_MAP` in the script (it is intentionally not auto-generated to make the override site obvious).
- `ModuleNotFoundError: stable_baselines3` from your own code → loco-mujoco does not install sb3; this is dispatcher mode (JAX-native). If you need sb3, install it manually inside the container and write your own training script outside `scripts/train_rl_policy.py`.
- `ModuleNotFoundError: torch` → loco-mujoco is JAX-only; PyTorch is intentionally absent. Use JAX/Flax for any custom training code.
